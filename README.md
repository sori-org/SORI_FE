# SORI\_FE

"소상공인의 목소리, SORI" 프로젝트의 프론트엔드 저장소입니다. SORI는 SNS 마케팅에 어려움을 겪는 소상공인들을 위해 AI 기반으로 맞춤형 마케팅 콘텐츠를 자동으로 생성해주는 웹/앱 서비스입니다.

## 프로젝트 소개

[cite\_start]과거 소상공인들의 주요 홍보 수단은 전단지, 배너 등 인쇄매체 중심이었으나, 최근에는 SNS, 블로그, 온라인 광고 등 디지털 플랫폼 중심으로 빠르게 변화하고 있습니다[cite: 4]. [cite\_start]이러한 변화 속에서 온라인 마케팅의 중요성은 높아지고 있지만, 많은 소상공인들은 콘텐츠 제작과 SNS 활용에 어려움을 겪고 있으며, 시간적·경제적 부담으로 인해 효과적인 온라인 마케팅 실행이 쉽지 않은 상황입니다[cite: 5]. [cite\_start]특히 조사결과 대부분의 소상공인의 연령대는 50\~60대로 나타났는데 [cite: 6] [cite\_start]이들은 SNS 사용 경험이 적고, 콘텐츠 기획·디자인 역량이 부족하여 전문가 의존도가 높고 비용 부담이 큽니다[cite: 6]. [cite\_start]기존 마케팅 대행 서비스는 월 수십만 원 이상의 비용이 소요되며, 디자인 외주 역시 1건당 수만 원 이상의 단가로 소상공인이 지속적으로 이용하기에는 경제적 부담이 큽니다[cite: 7]. [cite\_start]또한, 변화하는 소비자 트렌드와 SNS 알고리즘에 따라 정형화된 콘텐츠로는 소비자의 관심을 끌기 어려운 상황입니다[cite: 8]. [cite\_start]따라서, 초보자도 쉽게 사용할 수 있고 [cite: 9][cite\_start], 시간과 비용을 절감할 수 있으며 [cite: 10][cite\_start], 차별화된 콘텐츠를 자동으로 생성해주는 서비스에 대한 수요가 높아지고 있습니다[cite: 11].

[cite\_start]이에 따라, 본 프로젝트에서는 AI 기반 자동 콘텐츠 생성 플랫폼 "소리(SORI)"를 개발하여, 소상공인들의 마케팅 효율성을 높이고 지역 경제 활성화에 기여하고자 합니다[cite: 12]. [cite\_start]'소리'라는 이름은 시장의 소리에 귀 기울이고, 소상공인의 목소리를 마케팅 콘텐츠로 울려 퍼지게 한다는 의미를 담고 있습니다[cite: 15]. [cite\_start]이 서비스는 사용자가 간단한 조작만으로 트위터, 인스타그램 등 소셜 미디어에 적합한 마케팅 콘텐츠를 생성할 수 있도록 돕습니다[cite: 16]. [cite\_start]AI를 활용해 이미지와 텍스트 형식, 네컷만화, 표지 총 3가지 형태로 결과를 제공하며 [cite: 17][cite\_start], 날씨 데이터, 리뷰 데이터, 트렌드 데이터, 지역 행사 정보 중에서 선택하여 콘텐츠에 반영함으로써 사용자 맞춤형 마케팅 자료를 효과적으로 생성할 수 있습니다[cite: 17]. [cite\_start]이를 통해 정형화된 마케팅 도구와 차별화된 독창적인 콘텐츠를 제공하며, 콘텐츠 제작 시간을 단축하고 마케팅 비용을 절감하는 동시에, 도달률과 고객 참여율을 효과적으로 높일 수 있도록 지원합니다[cite: 18]. [cite\_start]궁극적으로는 소상공인의 마케팅 효율성 증대와 지역 경제 활성화에 기여하는 것을 목표로 합니다[cite: 21].

### 주요 기능

  * [cite\_start]**마케팅 콘텐츠 자동 생성**: 사용자의 간단한 선택(홍보 채널, 홍보 대상, 타겟층, 포함 정보 등)을 기반으로 AI가 자동으로 마케팅 게시물을 생성합니다[cite: 218].
  * [cite\_start]**다양한 콘텐츠 형식**: 이미지/텍스트 형식, 네컷만화, 표지 등 3가지 형태로 콘텐츠를 제공합니다[cite: 17].

  * [cite\_start]**My 페이지**: 프로필 수정, 로그아웃, 가게 정보 수정, 가게 정보 등록, 가게 정보 삭제를 할 수 있습니다[cite: 250].
  * [cite\_start]**기록 보기**: 그동안 생성했던 마케팅 게시물을 확인할 수 있으며, 오래된 순 또는 최신 순으로 정렬이 가능합니다[cite: 275, 727].
  * [cite\_start]**카카오 로그인**: 카카오 로그인/오래된순 or 최신순으로 정렬이 가능합니다[cite: 275].

### 개발 과정에서 직면한 문제점 및 해결 방안

[cite\_start]프론트엔드 개발 과정 중 다양한 기술적 난관에 직면했으나, 적극적인 디버깅과 정보 탐색을 통해 이를 해결하고 프로젝트를 성공적으로 완수할 수 있었습니다[cite: 59].

#### [cite\_start]1. CORS (Cross-Origin Resource Sharing) 문제 [cite: 60]

  * [cite\_start]**문제점**: 개발 환경(http://localhost:5173)에서 백엔드 서버([http://ec2-44-208-199-212.compute-1.amazonaws.com:8000](https://www.google.com/search?q=http://ec2-44-208-199-212.compute-1.amazonaws.com:8000))로 직접 HTTP 요청을 보낼 때, 브라우저 보안 정책인 CORS에 의해 요청이 차단되는 문제에 직면했습니다[cite: 61]. [cite\_start]초기에는 `/kakao/callback` 엔드포인트에 대한 POST 요청에서 이 문제가 발생하여 Kakao 로그인 연동에 어려움을 겪었습니다[cite: 62].
  * **해결 방안**:
      * [cite\_start]**Vite 프록시 설정**: 개발 서버(config.js)에 `/api` 경로에 대한 프록시 설정을 추가하여 `http://localhost:5173/api` 요청이 백엔드 서버로 우회되도록 구성했습니다[cite: 64]. [cite\_start]이를 통해 브라우저가 직접적으로 Cross-Origin 요청을 보내는 것을 방지했습니다[cite: 65].
      * [cite\_start]**백엔드 CORS 허용 출처 설정**: 백엔드(FastAPI의 CORS middleware)에서 `http://localhost:5173` 출처로부터의 요청을 명시적으로 허용하도록 설정하여 개발 환경에서의 통신이 가능하도록 했습니다[cite: 66]. [cite\_start]이 두 가지 방법을 병행하여 CORS 문제를 해결하고 개발 환경을 안정화할 수 있었습니다[cite: 67].

#### [cite\_start]2. 데이터 유효성 검사 (422 Unprocessable Entity) 문제 [cite: 68]

  * [cite\_start]**문제점**: `POST /api/content/inputs` 엔드포인트로 `formData`를 전송했을 때, 백엔드로부터 422 Unprocessable Entity 오류가 지속적으로 발생했습니다[cite: 69]. [cite\_start]콘솔에 출력된 `formData` 객체를 확인했을 때는 데이터가 모두 채워져 있었음에도 불구하고 오류가 발생하여 초기 진단에 어려움이 있었습니다[cite: 70].
  * **해결 방안**:
      * [cite\_start]**키 이름 불일치 파악 및 해결**: 초기에는 프론트엔드에서 camelCase(`ageRange Target`, `contentFormat` 등)로 데이터를 전송하고 있었으나, 백엔드 스키마가 snake\_case(`age_range_target`, `content_format` 등)로 정의되어 있음을 발견했습니다[cite: 72, 73]. [cite\_start]`formData` 객체의 키를 camelCase에서 snake\_case로 변환하는 유틸리티 함수(`camelToSnake`)를 구현하고, Axios 요청 직전에 이 함수를 적용하여 문제를 해결했습니다[cite: 74, 77].
      * [cite\_start]**Nullable 필드 값 불일치 해결**: 키 이름 변환 후에도 422 오류가 간헐적으로 발생했습니다[cite: 78]. [cite\_start]백엔드 스키마에서 `promotion_name`, `user_image`, `user_prompt` 등이 `string | null` 타입으로 정의되어 있었으나, 프론트엔드에서는 빈 문자열(`''`)을 보내고 있었음을 파악했습니다[cite: 79]. [cite\_start]백엔드의 유효성 검사가 `null` 또는 비어있지 않은 문자열을 기대할 수 있음을 인지하고, `initial FormData`에서 해당 필드들을 `null`로 초기화하고, 사용자 입력이 없을 시에도 `null`을 보내도록 수정하여 문제를 최종적으로 해결했습니다[cite: 80].
      * [cite\_start]**백엔드 로그 분석의 중요성**: 이 과정에서 백엔드 서버(`sori-api`)의 로그를 면밀히 분석하는 것이 문제 해결에 결정적임을 체감했습니다[cite: 81]. [cite\_start]422 Unprocessable Entity와 함께 출력되는 상세한 유효성 검사 오류 메시지(예: "Field promotion\_name may not be empty string, must be null or non-empty string")를 통해 정확한 원인 필드를 파악하고 해결책을 도출할 수 있었습니다[cite: 82].

#### [cite\_start]3. 예외 처리 및 핸들링 [cite: 83]

  * [cite\_start]**문제점**: 프로젝트 초기 개발 단계에서 API 요청 처리 중 발생하는 다양한 예외 상황에 대한 체계적인 처리가 미흡했습니다[cite: 85]. [cite\_start]이로 인해 다음과 같은 문제점이 발생했습니다: 클라이언트에 구체적 오류 정보 없이 500 Internal Server Error가 빈번히 반환됨 [cite: 87][cite\_start], 디버깅 프로세스 복잡성 증가 및 문제 해결 시간 지연 [cite: 88][cite\_start], 클라이언트 측에서 적절한 복구 조치나 사용자 안내 어려움 [cite: 89][cite\_start], 외부 API(카카오 인증 등) 연동 시 발생하는 예외 처리 부재[cite: 90].
  * **해결 방안**:
      * [cite\_start]**HTTP 예외 표준화**: FastAPI의 `HTTPException`을 활용하여 상황별 적절한 HTTP 상태 코드와 상세 메시지를 반환했습니다[cite: 93]. [cite\_start]주요 구현 사례로는 콘텐츠 조회 시 콘텐츠가 없을 경우 404 Not Found 응답 [cite: 95, 96, 97][cite\_start], 권한 없는 콘텐츠 접근 시 403 Forbidden 응답 [cite: 98, 101, 102][cite\_start], 가게 등록 시 이미 등록된 가게인 경우 400 Bad Request 응답 [cite: 103, 104] 등이 있습니다.
      * [cite\_start]**외부 API 통신 오류 처리**: 카카오 OAuth 인증 과정에서 발생할 수 있는 다양한 예외 상황에 대한 처리를 구현했습니다[cite: 106]. [cite\_start]예를 들어, 카카오 토큰 요청 실패 시 400 Bad Request 응답 [cite: 108, 109, 110][cite\_start], 토큰 응답에 `access_token`이 없는 경우 500 Internal Server Error 응답 [cite: 111, 112] 등이 있습니다.
      * [cite\_start]**데이터 파싱 및 변환 오류 처리**: JSON 데이터 파싱 오류 등에 대한 `try-except` 블록을 사용했습니다[cite: 114]. [cite\_start]예시로 `external_sources` JSON 파싱 시 예외 처리 [cite: 116, 117, 118, 119, 120]가 있습니다.
      * [cite\_start]**데이터베이스 연산 오류 처리**: 데이터베이스 CRUD 작업 시 발생 가능한 예외 상황을 처리하고 [cite: 122][cite\_start], 트랜잭션 관리 및 롤백 처리를 구현했습니다[cite: 123]. [cite\_start]예시로 이미지 URL 저장 시 예외 처리 및 롤백 [cite: 127, 128, 129, 130, 131, 132][cite\_start], 가게 등록 시 예외 처리 [cite: 133, 134, 135, 136, 137, 138, 139, 140, 141, 142] 등이 있습니다.
      * [cite\_start]**자원 해제 보장 패턴**: `try-finally` 블록을 사용하여 데이터베이스 세션 등의 자원 해제를 보장했습니다[cite: 144]. [cite\_start]`get_db()` 함수에서 데이터베이스 세션 자원 해제를 보장하는 것이 예시입니다[cite: 146, 147, 148, 149, 150, 151, 152].
      * [cite\_start]**토큰 인증 및 권한 검증**: JWT 토큰 검증 실패, 권한 없는 리소스 접근 등에 대한 예외 처리를 구현했습니다[cite: 154]. [cite\_start]`Depends`를 통한 `current_user` 의존성 주입 및 검증을 사용했습니다[cite: 155]. [cite\_start]예시로 리프레시 토큰 검증 [cite: 159, 160, 161][cite\_start], 사용자 존재 여부 검증 [cite: 162, 163, 164] 등이 있습니다.
      * [cite\_start]**파일 업로드 처리 예외 대응**: 콘텐츠 이미지 업로드 기능에서 발생할 수 있는 다양한 예외 상황에 대한 처리를 구현했습니다[cite: 166]. [cite\_start]필수 파일 업로드 검증 [cite: 171][cite\_start], 콘텐츠 존재 여부 검증 [cite: 174, 175, 176][cite\_start], 파일 저장 시 발생할 수 있는 I/O 예외 처리 [cite: 177, 178, 179, 180, 181, 182, 183, 184, 187, 188, 189, 190][cite\_start], 기타 예외 처리 [cite: 191, 192, 193, 194] 등이 포함됩니다.
  * [cite\_start]**성과 및 개선 효과**: 이러한 예외 처리 및 핸들링을 통해 클라이언트에 명확한 오류 정보를 제공하고 (404 Not Found: 리소스 미존재, 400 Bad Request: 잘못된 요청 형식, 401 Unauthorized: 인증 실패, 403 Forbidden: 권한 없음, 409 Conflict: 리소스 충돌(중복 등), 422 Unprocessable Entity: 유효성 검사 실패, 500 Internal Server Error: 서버 내부 오류) [cite: 196, 197, 198, 199, 201, 202, 203, 204][cite\_start], 트랜잭션 안정성을 확보하며 (데이터베이스 작업 중 예외 발생 시 일관성 있는 롤백 처리 [cite: 206][cite\_start], 파일 업로드와 데이터베이스 업데이트의 원자성 보장 [cite: 207][cite\_start]), 외부 API 연동 안정성을 향상시키고 (카카오 OAuth 인증 과정에서 발생할 수 있는 다양한 오류에 대한 구체적 핸들링 [cite: 209][cite\_start], 토큰 갱신 실패, 인증 서버 응답 오류 등에 대한 명확한 오류 메시지 제공 [cite: 210][cite\_start]), 디버깅 및 문제 해결 효율성을 높였습니다 (구체적인 오류 메시지를 통한 문제 지점 신속 파악 [cite: 212][cite\_start], 예외 발생 시 관련 컨텍스트 정보(사용자 ID, 콘텐츠 ID 등) 포함 [cite: 213]).
